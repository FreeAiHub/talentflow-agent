## TL;DR

1. **JobSpy не поддерживает Djinni и Work.ua.** Заявленные в
   `src/talentflow/parsers/jobspy_parser.py` источники
   `("djinni", "work_ua", "linkedin", "indeed")` — выдумка: библиотека
   работает с `linkedin, zip_recruiter, indeed, glassdoor, google, bayt,
   naukri, bdjobs`. Основной источник MVP через JobSpy недостижим.
2. **Djinni отдаётся обычным HTTP-клиентом.** `https://djinni.co/jobs/`
   возвращает `200` на `curl` с честным User-Agent, никакой анти-бот защиты на
   публичном листинге не сработало.
3. **`robots.txt` Djinni разрешает `/jobs/`.** Запрещены только `/jobs2`,
   `/q`, `/developers`, `/free-jobs`, `/set_lang`.
4. **Есть sitemap** — `https://djinni.co/sitemap.xml` перечисляет URL вакансий
   вида `https://djinni.co/jobs/{id}-{slug}/`.
5. **Вывод:** для MVP Djinni парсится напрямую `httpx` + разбор HTML. Ни Apify,
   ни Firecrawl, ни прокси на старте не нужны. Это ноль долларов и один день
   работы.

## 1. JobSpy: что он реально умеет

Источник: [README JobSpy](https://raw.githubusercontent.com/speedyapply/JobSpy/main/README.md).

Поддерживаемые площадки (`site_name`):

```
linkedin, zip_recruiter, indeed, glassdoor, google, bayt, naukri, bdjobs
```

**Djinni и Work.ua в списке отсутствуют.** Более того, `work_ua` не
поддерживается ни одной известной обёрткой.

Полезные факты из того же README, которые стоит учесть:

| Факт | Значение |
|------|----------|
| Indeed | «лучший скрапер на данный момент, без rate limiting» |
| LinkedIn | «самый ограничивающий, обычно режет примерно на 10-й странице с одного IP. Прокси практически обязательны» |
| Лимит выдачи | все площадки отдают примерно до 1000 вакансий на один поисковый запрос |
| Блокировка | `429` — сайты агрессивно банят; рекомендуется пауза между запросами и прокси |
| Python | требуется `>= 3.10` |

Статус проекта: README отдаётся из `speedyapply/JobSpy`, при этом картинки
ссылаются на `cullenwatson/JobSpy` — то есть репозиторий переехал или
форкнут. `[не проверено]` — какой из них канонический и как давно выходил
последний релиз.

**Что это значит для нас.** JobSpy остаётся полезен как источник для LinkedIn
и Indeed на будущее (фаза 2, международное расширение), но **не может быть
основой Дня 2**, потому что главный источник MVP — Djinni.

## 2. Djinni: проверка вживую

Проверено `curl` 23.09.2026 с User-Agent `Mozilla/5.0 (compatible; TalentFlowBot/0.1)`.

### robots.txt

```
User-agent: *
Disallow: /jobs2
Disallow: /q
Disallow: /developers
Disallow: /free-jobs
Disallow: /set_lang

Sitemap: https://djinni.co/sitemap.xml
```

`/jobs/` **не запрещён**. Это разрешает парсинг листинга вакансий при
соблюдении вежливости (паузы между запросами).

### Листинг

- `https://djinni.co/jobs/` → HTTP `200`
- В HTML присутствуют ссылки вида:

```html
href="/jobs/849872-product-owner/"
href="/jobs/849871-crm-manager/"
href="/jobs/849869-devops-backend-engineer/"
```

То есть **листинг уже содержит id и slug** — отдельный запрос на карточку нужен
только ради полного описания.

### Sitemap

`https://djinni.co/sitemap.xml` содержит URL вакансий того же вида
`https://djinni.co/jobs/{id}-{slug}/`. Актуальные id на дату проверки —
в районе 849000–850000, встречаются и старые (десятки тысяч), то есть sitemap
отдаёт накопленный корпус, а не только свежее.

**Практический вывод:** свежие вакансии удобнее брать с листинга (там порядок
по дате), а sitemap — как способ добрать пропущенное и как источник id.

## 3. Сравнение инструментов

| Инструмент | Умеет Djinni | Анти-бот | Цена | Вердикт для MVP |
|------------|--------------|----------|------|-----------------|
| **httpx + разбор HTML** | да, проверено | не сработал на `/jobs/` | $0 | **Основной путь** |
| JobSpy | **нет** | — | $0 | Не подходит для Djinni; брать для LinkedIn/Indeed в фазе 2 |
| Apify (`parseforge/djinni-co-scraper`) | актор существует | берёт на себя | `[не проверено]` | Резерв, если Djinni начнёт блокировать |
| Firecrawl | теоретически | берёт на себя | `[не проверено]` | Избыточен: страница — обычный HTML |
| Crawl4AI | теоретически | — | $0, self-hosted | Избыточен по той же причине |
| Scrapling | теоретически | заявляет обход Cloudflare Turnstile | $0 | Держать в уме как замену httpx при появлении защиты |
| Playwright | да | тяжёлый | $0 | Не нужен: JS-рендеринг для листинга не требуется |

Цены Apify, Firecrawl и Scrapling **не проверены** — в этом отчёте они не
приводятся, чтобы не выдавать догадку за факт. Проверить перед тем, как
закладывать в бюджет.

## 4. Вежливость и устойчивость

Требования, которые нужно заложить в парсер с первого дня:

- **Задержка между запросами.** Не меньше 1–2 секунд; при 429 — экспоненциальный
  откат и пауза на десятки минут.
- **Честный User-Agent** с контактом разработчика — сейчас используется
  `TalentFlowBot/0.1`. Подставить реальную почту перед продакшеном.
- **Ограничение параллелизма.** Не больше 2–3 одновременных соединений.
- **Кэш карточек.** Описание вакансии не меняется — повторный запрос по тому же
  id бессмыслен.
- **Дедупликация по id из URL.** Он уже есть в ссылке, отдельный хэш не нужен.
  Это снимает половину задачи Дня 2.
- **Пауза на ночь.** Ночью новых вакансий почти нет — незачем создавать нагрузку.

## 5. Правовые ограничения

- `/jobs/` разрешён `robots.txt` — парсинг листинга не нарушает технические
  ограничения сайта.
- Вакансии — публичные данные о компаниях, а не персональные данные
  соискателей. Это принципиально: **резюме и контакты соискателей собирать
  нельзя** — это уже персональные данные под GDPR и украинским законом.
- Условия использования сайта отдельно не изучались `[не проверено]`. Перед
  коммерческим использованием стоит прочитать ToS целиком.
- Не выдавать себя за другое лицо и не обходить авторизацию: парсим только то,
  что видно без логина.

## 6. Рекомендация

**Для Дня 2 (MVP):**

```
httpx.AsyncClient
  → пауза 1–2 с между запросами
  → GET https://djinni.co/jobs/ (листинг, при необходимости ?page=N)
  → разбор ссылок href="/jobs/{id}-{slug}/"
  → опционально: GET карточки ради полного описания
  → Vacancy(id=..., title=..., company=..., url=..., description=...)
```

Обязательно: тесты на **записанных HTML-фикстурах**, без живой сети в CI.
Это прямо прописано в DoD Дня 2.

**Fallback при появлении блокировки** — в таком порядке:

1. Паузы и честный User-Agent (сначала просто сбавить темп).
2. Scrapling вместо httpx.
3. Apify-актор по Djinni (цена требует проверки).
4. Playwright.

**Для фазы 2:** JobSpy для LinkedIn и Indeed, отдельным адаптером рядом —
не вместо парсера Djinni.

## 7. Что нужно проверить руками

1. Сколько вакансий на одной странице листинга и как устроена пагинация —
   `?page=N` или бесконечная прокрутка.
2. Есть ли на карточке вакансии структурированные данные (`application/ld+json`) —

4. Полный текст ToS: разрешён ли автоматизированный сбор.
5. Канонический репозиторий JobSpy и дата последнего релиза.
6. Цены Apify-актора по Djinni и Firecrawl — если понадобится fallback.
