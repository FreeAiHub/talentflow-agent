### Где дорогая модель действительно лучше

`claude-fable-5.1` — единственная с заметным отрывом: **код 81.6 против 71.5**
(+14%) и агентность 57.9 против 50.9 (+14%). Это и есть та работа, за которую
стоит платить: длинные цепочки правок кода, где 14% разницы превращаются в
меньше сломанных попыток. Держать её для чтения файлов и прогонов тестов —
выбрасывать деньги.

## Что ещё видно в каталоге

**`:batch`-варианты дешевле примерно вдвое** — `glm-5.3-flash:batch` стоит
$0.06/$0.20 против $0.15/$0.50. Но batch — это асинхронная очередь, а не
интерактив: для агента, который ждёт ответ, чтобы сделать следующий шаг, не
годится. Для массовой обработки — да.

**Дешёвых моделей с полным набором возможностей много.** Во всём каталоге из
455 моделей **386 поддерживают инструменты и 372 — структурированный вывод**. В
снимке, отфильтрованном по «текст + инструменты + структурированный вывод»,
таких 343. То есть «умеет вызывать функции» давно перестало быть признаком
дорогой модели — это норма, а не преимущество.

**Но индекс качества есть лишь у 188 из 455**, и только у **121 из 343**
отфильтрованных. Для остальных `value` посчитать нечем: цена известна, качество
нет. Это ещё одна причина для своего замера — треть каталога не с чем сравнить.

**Лидер по отдаче за деньги — `z-ai/glm-5.3-flash:batch`**, но по причине выше
он для интерактивной работы не подходит. Среди интерактивных лидер —
`deepseek-v4-flash-0731`.

## Каких данных не хватает, чтобы понимать, где какая модель лучше

Это ответ на вопрос «что нам ещё нужно». Три пробела, и все три —
содержательные, а не технические.

### 1. Бенчмарки не про наши задачи

`intelligence_index`, `coding_index`, `agentic_index` — это **чужие замеры**.
`design_arena` меряет генерацию сайтов, игр и датавиза: 157 замеров на
`website`, 150 на `codecategories`, 149 на `gamedev`. Наших задач там нет
вообще:

| Наша задача | Есть ли замер |
|-------------|---------------|
| Скоринг вакансии по ICP | **нет** |
| Генерация письма без выдуманных фактов | **нет** |
| Извлечение структуры из `ld+json` | **нет** |
| Разбор HTML, устойчивый к смене вёрстки | **нет** |

Модель с высокой агентностью может оказаться плохой именно в оценке
релевантности вакансии — и наоборот. Мы этого не знаем.

### 2. Нет своего замера «качество на рубль» на реальных данных

Чтобы понять, где какая модель лучше **у нас**, нужен один прогон:

```
для каждой модели из шортлиста:
    прогнать 20 реальных вакансий через prompts/vacancy_scorer.md
    измерить: время, токены, стоимость, согласие с разметкой
    сравнить с эталоном (claude-fable-5.1)
```

Это тот же каркас, что нужен Дню 5 (evals) — и он же закрывает вопрос ротации.
Один инструмент, две задачи.

**Без него ротация построена на чужих бенчмарках и наших догадках.** Цены мы
знаем точно, качество на своих задачах — нет.

### 3. У Jev нет ни одного бенчмарка

В каталоге у `typesafe/jev-1.13` поля `benchmarks` нет вовсе, а в публичном
API его нет и самого. Мы знаем цену ($0.042/M вход, $0.00 выход) и что он
умеет решать. **Насколько хорошо он решает именно наши вопросы — неизвестно.**
Единственная известная цифра — заявление TypeSafe про 40–400× дешевле, и это
заявление, а не замер.

Проверяется тем же прогоном: тот же набор вакансий, тот же вопрос, но как
`score`-примитив вместо генерации. Сравнить согласие с разметкой и стоимость.

## Оговорка про источник

Публичный `openrouter.ai/api/v1/models` отдаёт **455 моделей** с ценой,
контекстом, поддерживаемыми параметрами и бенчмарками. Этого достаточно для
решения о выборе.

**Но API неполон.** `typesafe/jev-1.13` в нём отсутствует, хотя страница модели
живая и данные настоящие. Скрипт добавляет такие модели вручную из списка
`KNOWN_MISSING` — сейчас там одна запись. Проверять «есть ли модель в API»
недостаточно: путь `/api/v1/models/{author}/{slug}` отдаёт 404 для **всех**
моделей, а веб-страница — 200 даже для выдуманного слага. Смотреть надо
содержимое страницы.
