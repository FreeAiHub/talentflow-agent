# 🕸 Сетка агентов TalentFlow Agent

> Кто решает задачи, кто их проверяет и как результат попадает в репозиторий.
>
> [`AGENT-ROSTER.md`](AGENT-ROSTER.md) отвечает на вопрос «какие есть роли и на
> каких моделях». Этот документ отвечает на другой: **в каком порядке они
> работают**, чтобы задача из issue превратилась в проверенную правку, а не в
> отчёт «вроде сделано».
>
> **Обновлено:** 24.09.2026

---

## Три правила сетки

1. **Автор и проверяющий — разные модели и разные сессии.** Модель, написавшая
   правку, не подписывается под её приёмкой.
2. **Изоляция.** Каждый исполнитель работает в своём `git worktree` и своей
   ветке. Два агента не пишут в один рабочий каталог.
3. **Доказательство.** Результат принимается по выводу команды — тесты, прогон,
   SQL-запрос, код возврата. Отчёт без вывода не считается результатом.

Из этих трёх правил следует четвёртое, самое дорогое: **«не проверено» — это
нормальный результат**. Проверяющий имеет право сказать «опровергнуто» или «не
проверено», и это ценнее выдуманного «подтверждено».

## Состав сетки

| Роль | Что делает | Ступень 1 (дёшево) | Артефакт |
|---|---|---|---|
| **Координатор** | читает issues, ставит задачи, сводит результаты, создаёт PR | `deepseek-official/deepseek-flash` | план, ветки, PR |
| **Repo-Keeper** | репозиторий: issue → ветка → PR, CI, ссылки, статусы | `deepseek/deepseek-v4-flash-0731` | PR, комментарии в issues |
| **Решатель (Resolver)** | правит код или документы по конкретному issue | `deepseek/deepseek-v4-flash-0731` | коммит в своей ветке |
| **Постер** | собирает пост: факты из файлов, рубрика, канал, запреты | `deepseek/deepseek-v4-flash-0731` | пакет поста, запись в очереди |
| **Фактчекер** | сверяет пост с файлами проекта, ищет неподтверждённое | `z-ai/glm-5.3` (другое семейство) | вердикт по каждому утверждению |
| **Живой прогон** | запускает конвейер на настоящих данных и ключах | `deepseek/deepseek-v4-flash-0731` | числа: время, стоимость, доля выше порога |
| **Проверяющий (Verifier)** | независимая проверка DoD: `ПОДТВЕРЖДЕНО` · `ОПРОВЕРГНУТО` · `НЕ ПРОВЕРЕНО` | `z-ai/glm-5.3` | протокол проверки |
| **Приёмка** | мерж, канал, токены, ICP — человек | — | решение владельца |

Промпты ролей лежат в [`prompts/agents/`](../prompts/agents):
`08-repo-keeper.md`, `09-poster.md`, `10-fact-checker.md` — новые роли сетки;
`01`–`07` — базовые роли из ростера.

## Волны

Работа идёт волнами, а не «все на всё»:

```
Волна 1 · независимые задачи параллельно
   Решатель #28 ─┐
   Решатель #27 ─┤  каждый в своём worktree и своей ветке
   Постер       ─┤  (движок постинга — отдельный репозиторий)
   Живой прогон ─┘  (числа, а не правки)

Волна 2 · независимая проверка
   Verifier: тесты, воспроизведение, границы, побочные эффекты
   → ПОДТВЕРЖДЕНО / ОПРОВЕРГНУТО / НЕ ПРОВЕРЕНО

Волна 3 · свод
   Координатор: PR из ветвей, комментарии и закрытие issues, обновление статусов

Волна 4 · человек
   Владелец: приёмка PR, канал постинга, ICP, бюджет на живые прогоны
```

Зависимые задачи в одну волну не ставятся: параллельный запуск зависимых задач
жжёт токены впустую.

## Как запускается

Изоляция рабочей копии — скриптом, а не руками: руками легко создать копию от
устаревшего локального `main`, и тогда diff агента будет содержать чужие
изменения.

```bash
scripts/agent_worktree.sh 40 parsers-save
# каталог: /Users/investing/GitHub/tf-wt-40
# ветка:   fix/40-parsers-save (от origin/main)
```

Скрипт проверяет аргументы, берёт ветку от `origin/main` и печатает напоминание:
push и мерж делает координатор, исполнитель только коммитит в свою ветку.

Задание агенту:

```python
subagent(
    description="CONTRIBUTING привести к фактам (#36)",
    prompt=<содержимое prompts/agents/08-repo-keeper.md с заполненными полями>,
    provider="openrouter",
    model="deepseek/deepseek-v4-flash-0731",
    run_in_background=True,
)
```

Обязательные поля задания: абсолютный путь к копии, номер issue, границы файлов,
DoD, стоп-условие, что вернуть в отчёте. Субагент **не видит** чат координатора,
поэтому задание обязано быть самодостаточным.

Проверяющему всегда выдаётся **другая** модель, чем исполнителю, и отдельная
сессия: он читает diff и гоняет команды сам.

## Гейты: что решает только владелец

Сетка останавливается и не решает за человека:

| Гейт | Почему человек |
|---|---|
| Канал постинга и токен бота | это его аккаунт и его имя под постом |
| ICP и профиль отправителя | это факты о его бизнесе, выдумывать их запрещено |
| Бюджет на живые прогоны | расход реальных денег |
| Ключ LLM для скоринга | доступ к платному провайдеру |
| Мерж PR в `main` | в проекте нет автоматического мержа |
| Разметка ground truth для evals | метрика, размеченная агентом, смещена в его пользу |

## Чем сетка не является

- **Не автономным мержем.** Агенты готовят PR, принимает человек.
- **Не заменой разметке.** Ground truth для evals делает человек, иначе метрика
  точности ничего не значит.
- **Не «агентом на всё».** У каждой задачи один исполнитель: параллельные правки
  одного файла — это конфликт, а не скорость.
- **Не оправданием расходов.** Дорогая модель берётся только после
  зафиксированного провала дешёвой (правило — в [`MODEL-ROTATION.md`](MODEL-ROTATION.md)).
