# 🚀 Деплой TalentFlow Agent

> Практическая инструкция. Что проверено, а что требует вашего сервера —
> отмечено честно, потому что «работает у меня» не равно «задеплоено».

---

## Что нужно до начала

**Секреты.** Ничего не запустится без:

| Переменная | Где взять | Обязательна |
|------------|-----------|-------------|
| `POSTGRES_PASSWORD` | придумать | да — без неё compose откажется стартовать |
| `TALENTFLOW_OPENROUTER_API_KEY` или `TALENTFLOW_GROQ_API_KEY` | openrouter.ai / console.groq.com | для скоринга |
| `TALENTFLOW_TELEGRAM_BOT_TOKEN` | @BotFather | для уведомлений |
| `TALENTFLOW_TELEGRAM_CHAT_ID` | `getUpdates` после сообщения боту | для уведомлений |
| `TALENTFLOW_TELEGRAM_WEBHOOK_SECRET` | придумать | **иначе вебхук отказывает всем** |
| `TALENTFLOW_VAPI_WEBHOOK_SECRET` | дашборд Vapi | если используете голос |
| `TALENTFLOW_ICP_PROFILE` | ваш реальный профиль клиента | иначе оценки бессмысленны |
| `TALENTFLOW_SENDER_PROFILE` | ваш реальный опыт | иначе письма будут общими |

```bash
cp .env.example .env
# заполнить .env, затем:
docker compose up -d --build
```

Compose читает `.env` и для подстановки, и внутрь контейнера. Отсутствие файла —
немедленная ошибка, а не запуск с паролями по умолчанию.

## Вариант A: Coolify на своём VPS (рекомендуется)

[Coolify](https://next.coolify.io/pricing) self-hosted **бесплатен навсегда**,
все функции без ограничений; платить нужно только за сервер. Проверено 23.09.2026.

Почему так:

- Оплата уходит хостеру VPS, а не сервису, принимающему только карты. Для
  украинской компании это меньше платёжного трения.
- На том же сервере поднимается self-hosted Langfuse, если понадобится
  трассировка LLM.
- Данные не покидают вашу инфраструктуру — через конвейер идут описания
  вакансий и переписка с клиентами.

**Стоимость VPS не проверена** — цены Hetzner, DigitalOcean и аналогов в
отчётах не подтверждены. Это первое, что нужно уточнить перед покупкой.

Шаги:

1. VPS с Docker, минимум 2 ГБ памяти (FastAPI + PostgreSQL + планировщик).
2. Установить Coolify по их инструкции.
3. Подключить репозиторий, указать `docker-compose.yml`, задать переменные
   окружения в интерфейсе Coolify (не в файле на сервере).
4. Домен и HTTPS — средствами Coolify.
5. Включить `TALENTFLOW_SCHEDULER_ENABLED=true`.

## ⚠️ Один воркер — это не пожелание, а требование

Планировщик живёт в процессе приложения. **Каждый воркер запускает свой**, и
при двух воркерах конвейер пойдёт дважды.

```bash
# Правильно: один воркер, планировщик внутри
uvicorn talentflow.api.main:app --host 0.0.0.0 --port 8000

# Неправильно: два планировщика
uvicorn talentflow.api.main:app --workers 4
```

Если нужно масштабирование по воркерам — вынести планировщик в отдельный
процесс и выставить `TALENTFLOW_SCHEDULER_ENABLED=false` у API. Конвейер
идемпотентен, поэтому случайный дублирующий прогон потратит работу, но ничего
не испортит.

## Миграции

Применяются автоматически при старте контейнера (`docker-entrypoint.sh`).

Почему так: контейнер, обслуживающий трафик против несмигрированной схемы,
падает непонятно — ошибками про отсутствующую колонку в момент запроса вместо
внятного отказа на старте. `alembic upgrade head` идемпотентен, поэтому
перезапуск и масштабирование безопасны.

Пропустить миграции (например, при откате): `TALENTFLOW_SKIP_MIGRATIONS=1`.

## Регистрация вебхуков

Обе ручки **отказывают, пока не задан секрет** — это сделано намеренно, чтобы
незащищённый эндпоинт нельзя было оставить «на потом».

**Telegram:**

```bash
curl -X POST "https://api.telegram.org/bot${TOKEN}/setWebhook" \
  -d "url=https://ваш-домен/webhooks/telegram" \
  -d "secret_token=${TALENTFLOW_TELEGRAM_WEBHOOK_SECRET}"
```

Telegram пришлёт этот секрет обратно в заголовке
`X-Telegram-Bot-Api-Secret-Token`.

**Vapi:** секрет задаётся в дашборде Vapi (`server.secret`) и приходит в
заголовке `X-Vapi-Signature`. Несмотря на название, это **общий токен, а не
HMAC по телу запроса** — [документация Vapi](https://github.com/devflowinc/vapi-docs).
Проверяется сравнением постоянного времени.

## Бэкапы

```bash
./scripts/backup.sh backup          # дамп в ./backups, хранит 14 дней
./scripts/backup.sh list            # что есть
./scripts/backup.sh restore <файл>  # восстановление
```

Скрипт считает дамп мусором, если тот меньше килобайта: упавший `pg_dump`
пишет сообщение об ошибке, а не данные, и такой файл лучше не хранить.

**Проверка восстановления обязательна.** Бэкап, который никто не
восстанавливал, — это не бэкап, а надежда. Порядок проверки:

```bash
./scripts/backup.sh backup
docker compose down -v            # уничтожить данные
docker compose up -d
./scripts/backup.sh restore backups/talentflow_<timestamp>.sql.gz
curl -s localhost:8000/api/v1/stats | head -c 200
```

## Проверка после деплоя

```bash
curl -s https://ваш-домен/health
# {"status":"ok","version":"0.1.0"}

curl -s https://ваш-домен/api/v1/stats
# vacancies_total, llm_budget_remaining, scheduler_running: true, last_run
```

`/api/v1/stats` — главный индикатор. Смотреть на:

- `scheduler_running: true` — планировщик поднялся
- `last_run.status` — `ok`, `skipped` или `failed`
- `llm_budget_remaining` — не ушёл ли бюджет в ноль
- `applications_grounding_failed` — сколько черновиков забраковано за выдумки

**Первые 24 часа:** главное, что нельзя проверить заранее, — суточный прогон
без падений. Смотреть `last_run` раз в несколько часов.

## Что проверено, а что нет

**Проверено локально:** образ собирается, миграции применяются на пустой БД,
`/health` и `/stats` отвечают, вебхуки отказывают без секрета, цикл
`upgrade`/`downgrade` проходит, 253 теста зелёные.

**Не проверено:** запуск на живом сервере. Нет ни доступа к VPS, ни домена, ни
credentials. Всё, что можно было проверить без них, проверено; остальное —
работа для вас, и инструкция выше описывает её целиком.

**Требует уточнения:** цены VPS и стоимость выбранного хостинга.
