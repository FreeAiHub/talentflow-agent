# 🤖 Роли агентов TalentFlow Agent

> Кто что делает в проекте, на какой модели работает и по каким правилам.
> **Обновлено:** 23.09.2026

---

## Зачем это

Десятидневный план из [`DEVELOPMENT_PLAN.md`](../DEVELOPMENT_PLAN.md) рассчитан
на агентский автопилот: человек тратит 15–20 минут в день на приёмку, остальное
делают агенты. Чтобы это не превратилось в «несколько чатов, которые мешают друг
другу», роли разделены, и у каждой есть своя модель, свои границы и свой формат
результата.

Главный принцип разделения: **автор и проверяющий — всегда разные модели.**
Модель, написавшая код, не подписывается под его приёмкой.

| **Картинки, длинный контекст** | `google/gemini-3.8-flash` | $0.75 / $3.75 | Скриншоты, PDF, 1M контекста | — |

### Правило ротации

**Дорогая модель — только там, где дешёвая доказанно не справляется.** На
ступень выше переходят при зафиксированном провале (тесты не прошли, ответ не
сошёлся, агент зациклился), а не потому, что задача кажется важной.

Полная лестница, цены и обоснование — в [`MODEL-ROTATION.md`](./MODEL-ROTATION.md).
Причина простая: замер 23.09.2026 показал **$10.6 за день, из них 98% дали две
самые дорогие модели** — при том, что потолок их качества не использовался.

Модели доступны через провайдера `openrouter`. Полный список маршрутов
проверяется командой `list_subagent_models` в сессии координатора — состав
меняется, и таблица выше может отставать от реальности.

**Разрешённые маршруты** перечислены в `~/.dsh/settings.yaml`
(`subagent-model-selection.allowedModels`). Список читается при старте сессии,
поэтому после правки нужен перезапуск harness.

## Как запускать

Агент запускается как субагент с явным указанием провайдера и модели. Промпт
берётся из [`prompts/agents/`](../prompts/agents/) и заполняется под задачу дня.

```python
subagent(
    description="Реализовать парсер Djinni",
    prompt=<содержимое prompts/agents/02-builder.md с заполненными полями>,
    provider="openrouter",
    model="anthropic/claude-fable-5.1",
    run_in_background=True,
)
```

**Правила запуска:**

- Независимые задачи запускаются **параллельно** в одном сообщении.
- Зависимые — последовательно: сначала результат, потом следующий шаг.
- Задача формулируется самодостаточно: субагент **не видит** этот чат.
- Каждый промпт содержит путь к репозиторию, контекст, границы файлов,
  Definition of Done и стоп-условие.

---

## Общие правила для всех агентов

Эти пункты дублируются в каждом промпте — молчаливо предполагать их нельзя.

1. **Границы файлов.** В промпте перечислено, какие файлы можно трогать. Всё
   остальное — только чтение.
2. **Секреты.** Ключи, токены, `.env` не попадают ни в код, ни в промпты, ни в
   коммиты. Только имена переменных окружения.
3. **Факты.** Цена, версия, лимит тарифа — только со ссылкой на официальный
   источник. Не подтверждено — помечается `[не проверено]`.
4. **Запрет на выдумывание.** Если чего-то нет в репозитории или в найденных
   источниках — агент пишет об этом прямо, а не заполняет пробел догадкой.
5. **Стоп-условие.** Агент останавливается, когда достигнут DoD или когда
   упёрся в блокер. Бесконечное «улучшение» — нарушение.
6. **Отчёт о результате.** Финальное сообщение: что сделано, какие файлы
   изменены, чем подтверждено, что осталось за границей задачи.
7. **Браузер не трогать.** Общий браузер пользователя занят: для веба —
   только `web_search` и `web_fetch`. Инструменты `mcp__chrome-devtools__*` в
   параллельных агентах не используются.

## Разделение ответственности на примере одного дня

День 4 плана — LLM-скоринг:

```
Координатор   берёт день из плана, заполняет промпт Builder'а, запускает
     │
Builder       claude-fable-5.1 → реализует скорер, пишет тесты, коммитит в ветку
     │
Verifier      gpt-6-astra → читает diff, гоняет тесты сам, ищет:
     │        · есть ли обработка невалидного JSON от LLM
     │        · что будет при таймауте провайдера
     │        · не теряются ли вакансии при ошибке
     │        · соответствует ли `score` заявленному диапазону [0, 1]
     │
Builder       по замечаниям правит — только то, что подтверждено
     │
Координатор   сводит, обновляет чекбоксы, коммитит план, пушит
     │
Человек       15 минут: смотрит diff и метрики, мержит
```

Verifier **не правит код сам**. Его задача — найти проблемы и подтвердить их
воспроизведением, а не переписать всё по-своему.

## Дисциплина расходов

- Дорогие модели (`gpt-6-astra`, `claude-fable-5.1`) — только на задачах,
  где нужна настоящая работа головой: архитектура, сложная реализация, ревью.
- Дешёвые (`deepseek-v4-flash-0731`, `glm-5.3`) — на рутине: тесты по шаблону,
  переименования, документация, форматирование.
- Рисерч по сети (`gemini-3.8-flash`) дешевле, чем разбор той же темы
  дорогой моделью без доступа к свежим данным.
- Перед запуском пачки агентов координатор проверяет, что задачи
  действительно независимы — параллельный запуск зависимых задач жжёт токены
  впустую.

## Чего в этом процессе нет

Честно, чтобы не создавать ложных ожиданий:

- **Нет автоматического мержа.** Человек смотрит каждый PR. Агенты готовят, но
  не принимают решения о слиянии.
- **Нет полностью автономного десятидневного прогона.** Роль координатора
  требует сессии; между днями нужна точка входа человека.
- **Нет замены разметке.** Ground truth для evals в Дне 5 делает человек —
  иначе метрика точности скоринга ничего не значит.
- **Нет доступа к платным аккаунтам.** Интеграции (Apify, Instantly, Telegram)
  требуют ключей, которых у агентов нет: они пишут код и моки, ключи ставит
  человек.
