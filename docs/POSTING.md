# 📣 Ежедневный постинг проекта

> Как проект попадает в ленту: где живут посты, откуда берутся факты, что
> запрещено писать и кто включает публикацию.
>
> **Обновлено:** 24.09.2026

---

## Где это живёт

Посты готовит отдельный движок, он не часть этого репозитория:
`~/Jarvis/projects/freeaihub/posting-engine`. Конвейер — «пакет дня → проверки
Контроллера → очередь → публикация → отчёт».

В этом репозитории лежит другое: **источники фактов** и правила о том, что о
проекте можно утверждать. Модель репозиторий не читает — она получает тексты
файлов, перечисленных в реестре движка.

| Что | Где |
|---|---|
| Реестр проектов и каналов | `posting-engine/projects.yml` |
| Очередь постов | `posting-engine/state/queue.jsonl` |
| Отчёты прогонов | `posting-engine/reports/day-<дата>.md`, `host-<дата>.md` |
| Расписание | launchd `ai.freeaihub.posting`, ежедневно 06:30 |
| Слот проекта | 10:00, `Europe/Moscow`, язык `ru` |

Публикация выключена по умолчанию: без флага `--live` прогон холостой, а
`scripts/run-daily.sh` не включает живую отправку никогда — расписание готовит
черновики и отчёты.

## Источники фактов

Движок вырезает тексты из файлов, перечисленных в `projects.yml` → `facts`, и
передаёт их генератору одним блоком. Список для этого проекта:

- `README.md`
- `docs/PROJECT-STATUS.md`
- `docs/ROADMAP.md`
- `docs/CASE.md`
- `docs/EVAL-BASELINE.md`
- `prompts/README.md`

**Правило: новый факт попадает в посты только после того, как он появился в
одном из этих файлов.** Обещание, которого нет в репозитории, в пост не идёт,
даже если оно верно.

## Что запрещено писать

Проверки Контроллера блокируют пост, и часть запретов — не техническая, а
репутационная:

| Не пишем | Почему |
|---|---|
| Проценты готовности («сделано на 60%») | их нет в документах проекта; старые редакции выдумали их и уже удалены |
| LangChain, Pinecone, Airtable, Flowise, n8n | этих зависимостей нет в `pyproject.toml`. Четыре из пяти (LangChain, Pinecone, Airtable, n8n) перечислены как отказы в [`INTEGRATIONS.md`](INTEGRATIONS.md); Flowise там не упомянут, но в зависимостях его тоже нет — а прежние посты ссылались на несуществующий `docs/FLOWISE-INTEGRATION.md` |
| Выручку, MRR, конверсию, скидки, «гарантируем» | денежные обещания — блокирующая проверка |
| Проценты доступности и SLA | измерять их нечем, поэтому числа не публикуются |
| «Бесплатно» | только если формулировка подтверждена реестром (`allowed_claims`) |
| Любые цифры, которых нет в файлах-источниках | число без источника — догадка, а не факт |

Отдельно: **порог отбора в постах — `0.6`** (`TALENTFLOW_MIN_LEAD_SCORE`).
Порог `8.0` — из старой редакции промптов, в коде такого порога нет.

## Почему постов проекта пока нет

**Постов `talentflow-agent` в очереди сейчас нет вовсе, и это сделано
намеренно.** Семь постов, подготовленных на 21–27.09, сняты с очереди
24.09.2026 и перенесены в `state/queue-removed-2026-09-24.jsonl` с причиной: их
факты не подтверждались репозиторием — несуществующий
`docs/FLOWISE-INTEGRATION.md`, порог оценки 8.0 вместо 0.6, проценты готовности
60/40/30, CRM Airtable. Проверки Контроллера этого не ловят: они механические и
`source_facts` не сверяют. Оставить их в очереди означало бы, что при появлении
канала они уйдут в публикацию как есть.

Дальше постов не будет по второй, более простой причине: в `projects.yml` у
проекта стоит `channel: null`. Публиковать некуда — и это не сбой, а честное
состояние: канал называет владелец.

Пока каналов нет ни у одного проекта, движок работает в режиме `no_channels`:
перепроверяет очередь и не тратит денег на генерацию. Генерация включается сама,
когда в реестре появляется первый канал.

Чтобы публикация включилась, нужны три шага (решение владельца):

1. Назвать канал (например `@talentflow_agent`) и вписать его в `projects.yml`.
2. Положить токен бота в переменную окружения
   `TELEGRAM_BOT_TOKEN_TALENTFLOW_AGENT` (имя переменной — из `engine/publish.py`,
   само значение в реестре не хранится).
3. Проверить готовность: `python3 -m engine.readiness --root .` — код возврата
   `0` означает «готово». Сейчас он возвращает `1` по трём причинам: нет каналов,
   нет токенов и в репозиториях соседних проектов остались слитые секреты
   (подробности — в отчёте `engine.readiness`, он печатает вид секрета, файл и
   строку, но не значение).

## Проверка перед публикацией

```bash
cd ~/Jarvis/projects/freeaihub/posting-engine
python3 -m pytest tests -q            # тесты движка
python3 -m engine.readiness --root .  # секреты в репозиториях, каналы, токены
python3 -m engine.resweep --root .    # перепроверка очереди, ничего не публикует
```

`readiness` возвращает `1`, пока каналы не настроены. Это ожидаемый результат, а
не поломка: чинить его включением `--live` нельзя.

## Правила, которых держится сетка агентов

1. Пост без источника факта не публикуется.
2. Число без файла-источника — догадка; догадка в пост не идёт.
3. Публикацию включает только человек. Агент не запускает `--live` сам.
4. Фактчек поста идёт **против файлов проекта**, а не против текста поста.
5. Изменились факты в репозитории — пост перегенерируется, а не правится «на
   словах».
6. Расхождение между постом и документом — это дефект поста, а не документа.
