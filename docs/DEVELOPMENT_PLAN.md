## 🎯 Цель десяти дней

Один сквозной сценарий, работающий на сервере без ручного запуска:

```
Djinni → парсинг → дедупликация → БД → LLM-скоринг → фильтр по порогу
      → генерация отклика → подтверждение человеком → уведомление в Telegram
```

**Критерий готовности:** каждое утро в Telegram приходит подборка горячих
вакансий с готовыми черновиками откликов, а `/health` на публичном URL
отвечает `ok`.

**Что осознанно НЕ делаем в эти 10 дней:** голосовые агенты, RAG, свой
фронтенд-дашборд, биллинг, мультитенантность. Это фаза 2 — см.
[`ROADMAP.md`](ROADMAP.md).

## 🧱 Стек и решения

Выбор обоснован рисерчем от 23.09.2026 — отчёты в [`docs/research/`](research).
Пока проверен только слой парсинга: решения по LLM, инфраструктуре и аутричу
опираются на общие практики, а не на проверенные цифры. Что закрыть и к какому
дню — в [`docs/research/README.md`](research/README.md).

| Слой | Решение | Почему |
|------|---------|--------|
| Язык | Python 3.12 | Уже заявлен в CI, есть в `requires-python` |
| Пакеты и окружение | **uv** | Lock-файл, установка в разы быстрее pip, уже используется в `Dockerfile` |
| API | FastAPI + Pydantic v2 | Уже в стеке, OpenAPI из коробки |
| Качество кода | **ruff** (линтер + форматтер) + **mypy** | Один инструмент вместо flake8+isort+black |
| Тесты | **pytest** + pytest-asyncio + respx | Async-эндпоинты и мок HTTP |
| Парсинг | `httpx` + `json.loads` по `application/ld+json` (Djinni); JobSpy — только фаза 2 | Листинг отдаёт массив `JobPosting` (schema.org) с полным описанием: HTML-парсер не нужен, второй запрос на карточку тоже. JobSpy не умеет Djinni |
| БД | SQLite на дни 1–7 → PostgreSQL 17 | Ноль инфраструктуры на старте, переезд до деплоя |
| ORM и миграции | SQLAlchemy 2.0 async + Alembic | Миграции обязательны до первого деплоя |
| Планировщик | APScheduler в процессе приложения | Не нужна отдельная инфраструктура очереди на 1000 задач/день |
| LLM | OpenRouter как шлюз + fallback на Groq/Cerebras, structured output в Pydantic | Бесплатный тариф OpenRouter — 50 запросов/сутки, этого мало: нужен второй провайдер. Groq даёт 1 000/сутки бесплатно |
| Наблюдаемость | Langfuse self-hosted + структурные логи JSON | Бесплатно, видно каждый вызов LLM и его стоимость |
| CI | GitHub Actions: ruff → mypy → pytest → docker build | Сейчас гоняется только `compileall` |
| Деплой | Coolify self-hosted на своём VPS (fallback — Railway Hobby $5/мес) | Coolify бесплатен навсегда, платить только за VPS. Railway Free непригоден: $1 кредита и 0 кастомных доменов |

Точные версии пакетов и цены держим в отчётах рисерча, а не здесь, чтобы не
дублировать быстро устаревающие цифры в двух местах.

Что сделано и проверено — **23 теста, статистика сверена с ручными расчётами**:

| Часть | Состояние |
|-------|-----------|
| Метрики precision/recall/F1 | ✅ с 95% интервалами (Уилсон) |
| Перебор порогов 0.1…0.9 | ✅ с полной матрицей ошибок |
| Выбор порога по precision-полу | ✅ |
| CLI `python -m talentflow.evals` | ✅ работает |
| Разметка 15 вакансий | ⚠️ **предварительная**, требует человека |
| Сами оценки | ❌ нет модели |

> **Почему интервалы, а не одно число.** На 15 примерах интервал вокруг precision 0.8 — примерно ±14 процентных пунктов: пороги 0.4 и 0.6 в демонстрационном прогоне дают precision 0.833 [0.436; 0.970] и 1.000 [0.510; 1.000], то есть **неразличимы**. Поэтому порог выбирается по политике («точность важнее полноты»), а не по максимуму метрики. Это записано в `docs/EVAL-BASELINE.md` как определение, зафиксированное **до** измерения.
>
> **Почему не accuracy.** При 5 релевантных из 15 модель, всегда отвечающая «нет», даёт 67% accuracy и находит ноль. Метрика скрывает ровно тот отказ, ради которого оценка и делается.
>
> **Главное ограничение — разметка.** Её сделал агент, который писал промпт скоринга. По собственной методике это смещение в пользу автора: метрика измеряет согласие с собой. В фикстуре стоит `requires_human_confirmation: true`, и CLI печатает предупреждение при каждом запуске.
>
> **Одна метка уже спорная:** `Product Owner` отмечен релевантным, потому что управление проектами входит в ICP, но это продуктовая роль. При уточнении ICP метка может измениться — и это нормально, что это видно, а не спрятано.
>
> **Что закроет день:** ключ LLM, подтверждение 15 меток человеком (15 минут), добор до 30 вакансий. Пункт 5 из `EVAL-BASELINE.md` — прогнать Jev на тех же вакансиях: один прогон отвечает и на «точен ли скоринг», и на «стоит ли Jev своих денег».

> **Промпт переписан.** `response_generator.md` требовал `candidate_profile` и
> `rag_context`, которых в проекте нет: профилей кандидатов не заведено, RAG —
> фаза 2. Вместо них `sender_profile` и `cta` из настроек. Пример с зашитой
> ссылкой на Calendly убран. Добавлен явный запрет выдумывать факты.
>
> **Новый промпт `grounding_checker.md`.** Второй вызов LLM на каждое письмо:
> перечисляет утверждения черновика, которых нет в тексте вакансии. Вердикт
> `reject` означает, что черновик нельзя утвердить даже вручную — он хранится
> со статусом `grounding_failed` для разбора, но не как кандидат на отправку.
> Это главный риск LLM-аутрича: не плохой стиль, а уверенно приписанный клиенту
> стек, которого он не называл.

**Артефакты:** `src/talentflow/generators/`, `src/talentflow/api/main.py`

Два прогона подряд на настоящем Djinni:

```

  score skipped: no API key configured: set one of TALENTFLOW_OPENROUTER_API_KEY...
```

Второй прогон собрал **0 новых** — идемпотентность работает. Скоринг помечен `skipped` с причиной, а не `failed`: **парсинг не зависит от LLM, и кончившийся бюджет не должен его останавливать.** Это и есть проверка деградации.

> **Что не проверено:** суточный прогон без падений. Механизм есть (`max_instances=1` не даёт прогонам накладываться, `coalesce=True` схлопывает пропущенные), но 24 часа в этой сессии не помещаются.

**Агент:** Builder (Claude Fable 5.1) · **Проверяет:** Verifier (GPT-6 Astra)

**Definition of Done:** ⚠️ **Частично.** Механика проверена вживую, живая отправка ждёт токен бота.

```
без секрета           → HTTP 403
неверный секрет       → HTTP 403
верный секрет         → HTTP 200, approved
повторная доставка    → duplicate update
отклонение            → rejected
```

Кнопка меняет статус в БД, вебхук без секрета отклоняется, повторная доставка не переворачивает решение. **Не проверено:** что сообщение реально доходит до чата — для этого нужен токен бота.

> **Три вещи, ради которых этот день написан именно так.**
>
> **Секрет обязателен.** Без него любой POST на `/webhooks/telegram` мог бы утверждать черновики от имени ревьюера. Сравнение постоянного времени: сравнение с ранним выходом выдаёт секрет по байту.
>
> **Идемпотентность по `update_id`.** Telegram повторяет доставку. Без дедупликации повтор старого «утвердить», пришедший после нового «отклонить», молча перевернул бы решение. Ключ первичный, поэтому две одновременные доставки не могут выиграть обе.
>
> **Подтверждение нажатия — best effort.** К моменту, когда мы отвечаем «готово», решение уже записано. Уронить вебхук из-за не доехавшего тоста значило бы заставить Telegram повторять уже принятое решение.

**Артефакты:** `src/talentflow/notifiers/telegram.py`, `tests/test_telegram.py`

**Definition of Done:** ⚠️ **Частично.** Всё, что проверяется без сервера, проверено; публичного URL нет — нужен VPS и домен.

> **Две дыры, найденные при подготовке деплоя — обе сломали бы первый запуск.**
>
> **Postgres не работал вообще.** В `docker-compose.yml` стоял URL с драйвером `psycopg`, которого нет в зависимостях. Добавлен `asyncpg` — приложение само подставляет его к `postgresql://`.
>
> **Промпты не нашлись бы в контейнере.** Загрузчик искал `prompts/` относительно файла пакета: в исходниках это корень репозитория, а в контейнере пакет лежит в `site-packages`, и путь вёл в несуществующую папку. Теперь путь ищется по списку кандидатов, а образ задаёт `TALENTFLOW_PROMPTS_DIR` явно.
>
> **Закрыта дыра из первого аудита:** `/webhooks/vapi` принимал что угодно от кого угодно. Vapi присылает секрет в `X-Vapi-Signature` — **это общий токен, а не HMAC по телу**, что подтверждено их документацией; сравнение постоянного времени. Без настроенного секрета ручка отвечает 503, то есть отказывает, а не пропускает.
>
> **Образ:** непривилегированный пользователь, миграции при старте, healthcheck на стандартной библиотеке (в slim нет curl). **Compose:** healthcheck у базы, `depends_on` с условием, пароль обязателен через `${POSTGRES_PASSWORD:?}` — запуск с паролем по умолчанию невозможен.
>
> **Бэкапы:** `scripts/backup.sh` с дампом, хранением 14 дней и восстановлением. Дамп меньше килобайта считается мусором и удаляется — упавший `pg_dump` пишет ошибку, а не данные.

## 🔍 Ретроспектива

### Что сработало

**Рисерч окупился дважды.** Проверка Djinni вживую заняла десять минут и
показала, что `JobSpy` его не поддерживает, а листинг отдаёт готовый schema.org
JSON. Без этого День 2 был бы написан не с тем инструментом — а второй находкой
стало то, что HTML-парсер вообще не нужен: 1 запрос вместо 16.

**Проверка допущений перед работой.** Бесплатный OpenRouter даёт 50 запросов в
сутки при потребности ~250. Обнаружь это на Дне 4 в момент запуска — потеряли бы
день.

**Гейт подтверждения как отдельная функция.** `assert_sendable` живёт в
репозитории, поэтому API, планировщик и Telegram-бот прошли одну проверку, а не
завели каждый свою.

**Деградация вместо падения.** Конвейер продолжает парсить, когда LLM недоступен.
Это оказалось не теорией: именно так он вёл себя все девять дней без ключа.

### Что не сработало

**Субагенты.** Семь из семи упали на уровне харнесса — `claude-fable-5.1`,
`gpt-6-astra`, `gemini-3.8-flash`, `qwen3.8-max`, на разных задачах. День 1 успел
отработать, дальше критический путь пришлось вести самому. Это отклонение от
исходного замысла «автопилота на топовых моделях», и записывать его в достижения
нечестно: причина вынужденная.

**Дисциплина коммитов.** Трижды переписывал историю из-за backticks в сообщениях,
которые bash принимал за подстановку команд, и из-за файлов, уехавших не в тот
коммит. Лечится тем, что сообщения пишутся в файл и передаются через `commit -F`
— как и следовало сразу.

**Правка и её использование врозь.** Дважды `ruff --fix` удалял импорты как
неиспользуемые между двумя моими шагами. Импорт и код, который его использует,
надо добавлять одной операцией.

### Что стоит изменить

1. **Не начинать день, не проверив его главное допущение.** Djinni и OpenRouter
   показали, что это окупается за десять минут.
2. **Внешние credentials запрашивать в начале, а не обнаруживать в конце.**
   Ключ LLM и токен бота блокировали четыре дня из десяти, и узнать об этом
   можно было в первый.
3. **Не доверять документации, написанной до кода.** `INTEGRATIONS.md` обещал
   MVP за 2–3 дня и перечислял инструменты, которых в зависимостях нет.

### Цикл одного дня

```
1. Постановка      человек/координатор выбирает день и задачи из этого плана
2. Реализация      Builder работает в ветке day-N/<slug>, коммитит по частям
3. Проверка        Verifier независимо проверяет DoD и пытается опровергнуть результат
4. Приёмка         человек смотрит diff и метрики, 15–20 минут
5. Слияние         PR → main, чекбоксы дня закрываются, план обновляется
```

### Правила, которые не обсуждаются

- **DoD или ничего.** Задача не закрыта, пока не выполнены все пункты DoD. «Почти работает» не считается.
- **Ветка на день.** `main` остаётся рабочей. Никаких прямых коммитов в `main` в обход проверки.
- **Проверяющий не автор.** Verifier — другая модель, чем Builder. Самопроверка не принимается.
- **Секреты не в репозитории.** Ни ключей, ни `.env`, ни токенов в промптах и коммитах.
- **Не выдумывать факты.** Цены, версии и лимиты — только со ссылкой на источник. Не проверено — так и пишем.
- **Дешёвая модель для рутины.** Массовые механические правки не гоняем через дорогую модель.
