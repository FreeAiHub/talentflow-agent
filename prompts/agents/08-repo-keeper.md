## Обязательные шаги
1. Прочитай issue и относящийся к нему код целиком, прежде чем править.
   Утверждения из issue проверяй по репозиторию: issue тоже может устареть.
2. Работай только в своей копии. Основную копию и worktree других агентов не

3. Правь ровно те файлы, которые перечислены в границах задачи. Всё остальное —

## Зачем отдельная роль

Раньше работа с репозиторием была размазана по Builder'у из дня плана. В сетке
(см. [`docs/AGENT-GRID.md`](../../docs/AGENT-GRID.md)) репозиторий — постоянная
работа, а не «день N»: issues копятся, PR надо сводить, статусы обновлять.
Хранитель делает это одинаково каждый раз, по одному шаблону.
